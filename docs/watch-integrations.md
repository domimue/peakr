# Watch integrations (Phase 9)

What ships, what is switched off until a partner programme approves Peakr, what is confirmed and
what is not, and how to switch each platform on.

## What a user gets today (no approval needed)

- **Watch picker** in onboarding (between the quiz and the forecast, skippable) and in Profile → Watch:
  Garmin, COROS, Suunto, Apple Watch ("with the iPhone app") and Other watch (file export).
- **"Watch" action on every run, ride and swim**: a structured `.FIT` workout file written with
  Garmin's official FIT JavaScript SDK (`@garmin/fitsdk`) and, when a route is chosen, the route as
  `.GPX`. The user shares/saves the file and imports it into Garmin Connect, the COROS or Suunto app,
  or any other watch app. This is the universal fallback for every brand.
  - Run/bike: duration and heart-rate-zone targets; tempo, intervals and races use a pace range.
    A steady run on a chosen route gets **one step per route segment with its pace range**
    (grade-adjusted); structured sessions (intervals) keep their steps and the route goes as a course.
  - Swim: distance steps with pace per 100 m from CSS, rest steps, pool length (25 / 50 m).
  - A brick (bike → run) becomes two workouts, because a FIT workout has one sport.
  - Strength, walks and winter sports stay in the app (no watch platform takes them).
- If the SDK cannot encode on the device (JS-engine differences), the same file is generated by the
  Edge Function `watch/export`.

## What is built but switched off (feature flags)

| Platform | What Peakr does | Flag (Supabase secret) | App flag |
| --- | --- | --- | --- |
| Garmin Training API | pushes the next 14 days as structured workouts and schedules them on the Garmin calendar; **re-syncs on change** (moved workouts are updated, skipped/removed ones deleted) | `WATCH_GARMIN_TRAINING=1` | `garminWatch` |
| Garmin Courses API | publishes the chosen route as a course on Garmin Connect (publish only, it cannot read existing courses, so it is **not** an import path for Komoot) | `WATCH_GARMIN_COURSES=1` | `garminWatch` |
| Garmin Activity API | completed activities arrive by push notification into the same pipeline and deduplication as Strava (Garmin outranks Strava) | `WATCH_GARMIN_ACTIVITY=1` | `garminWatch` |
| COROS | OAuth, pushes the next 7 days as a training plan, re-sync on change (a workout COROS cannot delete is renamed and emptied), imports activities through their FIT files | `WATCH_COROS=1` | `corosWatch` |
| Suunto | OAuth, pushes routes (GPX) and workouts (FIT), webhook for completed workouts (FIT file) | `WATCH_SUUNTO=1` | `suuntoWatch` |

So yes: **auto-sync between Peakr and Garmin is built in both directions** – Peakr → Garmin via the
Training API (plan changes follow within seconds of the app being open, `useWatchAutoSync`) and Garmin
→ Peakr via the Activity API – and stays off only because Garmin has to approve the app first.

Everything lives in `supabase/functions/_shared/watch/` (pure TypeScript, also used by the app via
`packages/watch`), the Edge Functions `watch` and `watch-webhook`, the OAuth registry
(`_shared/providers.ts`) and the table `watch_pushes` (what was pushed, for re-sync).

## Where to apply

1. **Garmin** (priority): apply for **Starter Access** in the Garmin Connect Developer Program
   (developer.garmin.com/gc-developer-program/overview → Starter Access form), then create an app.
   Starter is push only, which is exactly what the Activity webhook uses; ask for Training, Courses
   and Activity in the application. The Personal tier is for one's own data and is no basis for a
   product. Enterprise is only needed for pull delivery, history or many users.
2. **COROS**: email **api@coros.com** and use the application form linked from COROS' API pages.
   They ask for an established platform with users, a registered company and an authorised technical
   contact, and the API terms. Mention the training-plan push and activity data.
3. **Suunto**: the **Apply now** form on the Suunto Partners page, choose **Suunto Cloud API** so the
   API agreement is issued; after acceptance you get access to the API Zone and subscribe to the
   Developer API product for the subscription key. Ask them directly whether planned structured
   workouts can be pushed.

## Switching a platform on

1. Register the redirect URI `https://<project>.supabase.co/functions/v1/oauth/callback` at the
   platform, and the callback URL of the notifications:
   `https://<project>.supabase.co/functions/v1/watch-webhook/<garmin|coros|suunto>?key=<WATCH_WEBHOOK_SECRET>`.
2. `supabase secrets set` the client id/secret (`GARMIN_CLIENT_ID`/`_SECRET`, `COROS_…`, `SUUNTO_…`),
   `WATCH_WEBHOOK_SECRET` (random), for Suunto `SUUNTO_SUBSCRIPTION_KEY` (and
   `SUUNTO_WEBHOOK_HMAC_SECRET` if Suunto signs the notifications).
3. Deploy: `supabase functions deploy oauth watch watch-webhook` and push the migration
   (`20261027000000_watch_pushes.sql`).
4. Correct the unconfirmed endpoint details above against the reference you received.
5. Set the platform's flag secret (`WATCH_GARMIN_TRAINING=1` …) and flip the app flag in
   `apps/mobile/src/config/feature-flags.ts` with the next release.

Disconnecting (Profile → Watch) revokes where the platform allows it, deletes the tokens, the pushes
and the activities that platform delivered. A Garmin deregistration notification does the same.
